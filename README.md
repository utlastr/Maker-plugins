# Maker 插件 4.5.4

## 4.5.4 更新入口与发布链路

刷新 Maker 控制台首页、自由画布或 UI 编辑器均触发签名更新检查。并发检查共用一次任务。
工具栏插件图标和扩展详情的「扩展选项」新增更新面板，支持「检查并更新」并显示版本与失败原因。
本机文件比浏览器已加载版本新时，自动重载扩展；任务执行中或画布未保存时等待空闲。
4.5.2 和 4.5.3 此前只在本机安装，GitHub 更新源仍是 4.5.1；本版补齐正式签名发布。
Cloudflare 共享画布读取本机固定安装目录的插件文件，刷新共享画布后采用更新后的文件。

## 4.5.3 平滑居中与原图元件裁切

选中居中改为约 180ms 的平滑缓出移动，保持缩放；手动拖动或滚轮立即停止自动移动。
基础卡片新增「元件裁切」：参考图片或生图结果连接后，点击「识别并裁切」，
复用官方 BBox 识别提示词、像素坐标校验和 manualNative 原尺寸裁切接口输出单个 PNG。
仅执行一次元件识别，不执行去字、生图、背景重建或遮挡补全。原图框内可见内容和透明度保留。
每张输入保存原请求 ID，重试复用识别结果。官方切图每边上限 4096 像素，超限在识图前拦截。
元件识别调用 Maker 云端 API，可能消耗积分。连接透明化卡可在裁切前后处理背景。

## 4.5.2 等待时间、边缘与选中定位

AI 命名与透明化、下一张图生成重叠执行，整批仍等待命名请求收尾并保留原请求 ID。
不改变云端模型或生图参数，不承诺云端处理时长。透明化启用完整去溢色，
对可确认的半透明背景混色边缘追加清理，保留 alpha、白色主体及已干净边缘；
不承诺任意复杂背景或不透明白边都能自动无损修复。
单击选中卡片后将该卡片置于画布中心，保持缩放；拖动、连线和编辑输入不触发居中。
桥接在请求提交前检查可用性，离线时使用 Native Messaging；提交后断线不自动换通道重发。

## 4.5.1 自动更新通信修复

修复本地更新启动器等待浏览器关闭输入管道的死锁：按 Native Messaging 消息长度读取完整请求，
立即转交更新器，不再等到整个输入流结束。此前直接运行诊断成功，并不能代表浏览器调用也能成功。
安装器和后续自动更新使用按版本命名的启动程序，避免旧进程占用可执行文件阻止升级。
已有旧版若一直停在“检查更新中”，需下载此版运行一次 Install.cmd 修复本地启动器；
仅刷新网页无法修复已经卡住的旧启动器。保持原扩展 ID 和固定安装目录。
回归测试模拟浏览器保持输入管道打开，确认无需关闭输入流即可收到回复。

## 4.5.0 批量迭代微调与 AI 命名

新增「迭代生图」模板及可独立连接到图片生成卡的「微调」卡片。
首次生成前输入和生成按钮禁用；只有最近一批全部图片成功且没有批次仍在运行时才启用。
填写修改点后，可点击微调卡或对应图片生成卡的生成按钮。提交时输入清空，内容保留在批次记录中。
整批每个任务分别使用其上一版成功图片及有效提示词，结合通用提示词、任务列表、本地描述，
通过 Maker 云端模型合并本轮修改；新要求覆盖冲突旧要求，其余要求保留。
所有任务的提示词均整理完成后才开始生图，避免 AI 理解失败造成半批重新生成。
AI 理解失败可点击「重试 AI 理解」恢复同一批原请求；不会重新提交已完成的理解请求。
每张新生成图片由 Maker 云端模型观察图片后自动命名。命名失败保留图片，在生成历史中刷新可恢复命名。
名称用于插件展示及下载，不重命名 Maker 的内部素材文件或改变其资源引用。
一张微调卡只连接一个生成卡，一个生成卡只接受一张微调卡，修改始终针对整批任务。

AI 理解和命名使用 Maker 账户积分。2026-11-17 实际验证收到「可用积分不足」，
因此未宣称云端理解、生图和命名已通过端到端验证；批次隔离及十任务对应关系的本地测试已通过。
运行本地测试：`node --test test/refinement.test.cjs`。
运行真实云端验证：`node scripts/verify-refinement-cloud.cjs`（会调用云端，可能消耗积分）。

原稿 BBox 坐标和元素绑定保留；普通尺寸素材继续使用官方图集预排。

## 4.4 生图批次历史

每次点击生成都会新建一批图片，不查询、等待或覆盖上一次生成；同一张生成卡也可以启动多个批次。
“查看生成历史”按第 1 次、第 2 次生成分组，显示时间、成功图片、生成状态和失败原因。
每批可单独预览、下载、刷新结果或取消。刷新只读取这一批的结果，不提交生图。
主画布继续显示已有图片，直到新批次有成功图片。新批次失败不会清空旧批次。
已有当前生成记录自动迁移为第一批；旧版本已经覆盖丢失的更早批次无法凭空恢复。
历史记录持久保存在该生成卡所属画布中，历史图片仍纳入插件任务归属管理。
主卡片移除“查询原任务”按钮。下游工作流跟随当前最新批次，历史窗口保留每批原始生成图片。
本版未提交付费生图或执行测试。

## 4.3.1 失败反馈与 BBox 通道

所有操作失败同时显示明确通知和对应卡片的原因，通知可关闭；不再仅写入后台日志。
点击运行立即显示准备状态；上游无输入、无处理结果等情况明确说明，不再空返回后表现为成功。
BBox 本地处理器增加带随机令牌的回环通信通道，复用同一个官方算法处理程序，不修改 Maker 源码。
安装器启动本地处理器并注册当前用户登录启动；同一通道支持 Edge 和 Chrome，不依赖浏览器 Native Messaging 注册是否可用。
处理器通过 Maker 实际的 /api/state 查询项目，修复此前误用不存在的 GET /api/projects 接口。
BBox 和 UI 组装在付费请求前检查处理器连接；失败保留原输入与请求记录。
本版未运行付费识图或完整 BBox 生图流程验收。

## 4.3 并行执行与非阻断状态

不同生成卡独立运行，不再使用全局单任务锁。同一张卡重复点击接回当前任务，不重复提交扣费请求。
同一处理节点被多个任务使用时内部排队；取消只针对当前任务及其自行启动的上游任务。
运行中仍可拖动、创建、删除及撤销；删除正在使用的节点时取消受影响任务。
普通等待、输入未到齐及可恢复失败只在卡片内显示，不弹出全局限制提示，不禁用生成和运行按钮。
单条生成失败不阻止队列内其余独立任务；结果未知时保留原请求供查询，不伪装生成成功。
后处理失败不改变已经成功生成的图片状态。签名、路径安全及持久保存异常仍保留系统提示。
透明化保留全部工作流元数据；旧透明结果可从上游恢复 BBox 映射。
切图缺少坐标时保持等待，不制造切图结果，也不把原图标为已经切分。
移除本地 32MB 导入上限、压缩 64KB 下限及复制卡片数量上限；浏览器可解码的其他图片先转换 PNG。
跨项目粘贴会复制引用图片和已有图片结果；UI 组装产物在目标项目重新构建。
参考图数量等模型条件仍依照真实接口配置，失败显示于对应卡片，不锁住其他任务。
图片查询读取官方图片记录，不再调用只支持视频的 query 操作；仅对明确的下载失败使用官方恢复下载。
更新扩展后，已保存且无任务的旧版本画布自动刷新；未保存或运行中保留当前页面。
本版仅执行语法和扩展加载检查，未运行测试或付费生图验收。

## 自动更新安装说明

自动更新依靠安装包中的本地更新器，不是浏览器自动更新解压文件夹。
Chrome 和 Edge 使用同一个 Windows 安装包，首次安装步骤如下：

1. 解压 Windows 安装包，运行 `Install.cmd`。
2. 打开 `chrome://extensions` 或 `edge://extensions`，开启开发者模式。
3. 点击“加载已解压的扩展”，选择 `%LOCALAPPDATA%\MakerWorkflow\extension`。
4. 不要选择下载目录、解压目录或源码目录中的 extension。
5. 打开 Maker 画布，通过“更新”查看版本及连接状态。

安装版在启动、启用、打开画布时检查更新，并每 15 分钟检查一次。
检查失败会重试；任务执行中或画布未保存时等待，不立即替换。
发布者需要发布新的 GitHub Release 安装包及签名更新文件，单独提交源码不会发布更新。
浏览器禁用或卸载扩展后不会检查；重新安装时再运行安装器并加载上述目录。

`Specified native messaging host not found.`，尚不能视为自动更新已接通。

## 我的模板与完整 BBox 工作流

空白处右键 → 我的模板，或官方“添加模板”窗口中的“我的工作流 → 我的模板”。
内置标准生图及 BBox 工作流；点一次添加整套独立组件和连线，不填充示例提示词。
支持将选中组件及内部连线保存为个人模板，模板中的本地图片引用会清空。

标准生图：通用提示词、任务列表、参考图片、图片压缩、图片生成、透明化、图片展示。
BBox：原始设计稿 → 图片压缩 → 原稿与识图输入 → 去文字与元素识别 → 批次编排
→ BBox预排 → 分离生图 → 切图与透明处理 → 素材确认 → UI资源包
→ 组装UI → 资源Meta → 引用检查 → 编辑器复核。

各步骤独立保存任务与结果，运行至此会依次运行尚未完成的上游；同源成功步骤复用结果。
去文字与识图、分离生图会调用官方模型，可能消耗积分，只有用户点击运行才提交。
素材确认需要查看切图并显式确认；编辑器复核提供编辑器入口，程序不能代替目视验收。
识图请求保存原请求编号；状态未知时先查询，不自动重复付费提交。
压缩输出严格小于180万字节的PNG副本，保留透明通道和原图，识图坐标换回原图尺寸。
六类素材、常态/按下态、普通文字Label、美术字分支的数据结构沿用官方规划。
识图、预排、图集裁切、UI组装、Meta均复用官方代码；不向官方画布创建隐藏卡片。

BBox处理器随安装包提供，需要Node.js 20以上及Maker登录。Meta沿用Maker的Python环境要求。
安装器会优先记录PATH中的Node，或查找当前Maker进程的Node。
此版本未执行模型请求、未进行整条BBox链路和编辑器验收，不把已完成的组件代码视为已验收交付。

## 内部安装与自动更新

Windows 安装包解压后运行 `Install.cmd`，无须管理员权限或 Codex；BBox处理需要Node.js。
首次在浏览器扩展页开启开发者模式，加载安装器显示的 extension 文件夹。
安装器只向当前用户注册本地更新器；之后启用扩展、启动浏览器或打开 Maker 画布时检查更新。
需要能读取的 GitHub Releases 下载地址。未配置仓库时安装器会询问 `OWNER/REPOSITORY`。
本发行方案使用公开 Release 附件，不把发布者 PAT 分发给使用者；这不提供下载访问控制。
检查失败保留当前版本；发现新版本，验证 RSA 签名及 SHA-256，再等待任务结束和画布保存后更新。
每次替换前备份扩展文件，替换失败恢复备份；数据留在原扩展的浏览器存储。
升级后若原画布未自动刷新，先保存再刷新页面。
发行包固定扩展 ID；它与以前本地开发目录的 ID 不同，旧用户切换前需备份原画布数据。

### 发布新版

发布机安装 Node 与 GitHub CLI，先执行 `gh auth login` 完成本人授权。
执行 `powershell -File scripts/publish.ps1 -Public`，创建 `Maker-plugins` 仓库并发布签名安装包。
GitHub 仓库路径使用 ASCII 名称，项目展示名称为“Maker 插件”。
签名私钥保存在发布者用户目录 `.maker-workflow-publisher/signing.pem`，不进入仓库或安装包。
后续修改扩展版本号，再执行同一发布命令；务必保留该私钥，否则既有安装器不会信任新签名。
仅打包执行 `node scripts/package-release.cjs OWNER/REPOSITORY`，输出位于 dist。
首次安装及自动更新流程尚未进行浏览器到本地程序的端到端验收。

节点直接显示在 Maker 自由画布中。插件独立拥有卡片、数据、创建、编辑、拖动、
尺寸、选择、删除、撤销、连接及结果展示，不创建或改写官方便签、图片卡片。
界面采用官方卡片的配色、边框、标题栏和菜单样式。

输入口为蓝色，输出口为橙色。输出口可分给多个下游。
从输出口拖到输入口；也支持依次点击输出口、输入口。
左键选中圆点或连线后右键断开；选中圆点时断开该圆点的全部连接。

多个通用提示词按连接顺序拼接，多个任务列表按连接顺序合并。
每行一条任务，可填写 `名称 | 描述`，合并后每批最多 100 条。
任务列表初始显示一条空输入行；下方加号新增，行右侧叉号删除。
粘贴多行会自动拆成多条任务，去除 `1.`、`一、`、`(1)` 等行首序号。
参考图片按连接顺序合并并去重，数量由所选官方模型限制。
三类上游输入全部可选，不要求全部连接，也不要求连接的卡片必须非空。
有内容的上游任务或参考图覆盖本地默认值；上游为空则恢复使用本地内容。
通用提示词允许为空，空内容直接忽略；仅有通用提示词时也能组装生成描述。
未连接参考图时，“跟随参考图”比例自动退回 1:1。官方服务仍自行校验最终请求。
遇到未确认的旧任务，点击生成会先查询旧任务，不直接重复提交。
状态仍未确认时保持等待；恢复状态后再次明确点击生成，才提交新的请求。

空白处右键展开「新建图片卡片」创建节点。
卡片标题栏拖动，右下角调整尺寸，右上角关闭。
选中卡片或连线后可删除；卡片可复制，编辑可撤销、重做。
Ctrl+C 复制选中卡片及内部连线，Ctrl+V 在指针附近粘贴，支持同一项目内跨画布复制。
Ctrl+V 可直接粘贴截图或剪贴板图片；选中参考图或生图卡时导入该卡，否则新建参考图卡。
文本框内保留正常文字粘贴；画布空白处粘贴纯文本创建通用提示词卡。
展开右键菜单后，在菜单外左键点击即可关闭；选择卡片类型后也立即关闭。
图片展示支持放大、单图下载和 ZIP 下载。
展示卡和结果弹窗按容器尺寸自动计算每页容量，页数随实际图片数量变化。
单张直接展示并下载，不显示筛选、选择和分页。10 张起显示勾选与全选。
不足 10 张且有多页时每 4 秒自动翻页，鼠标停留、编辑或手动翻页时暂停。
生成进度更新时跟随最新出图。单张直接保存图片，多张才打包 ZIP。
下载使用官方文件保存流程，保留图片原格式，不再显示 PNG/JPG/原图选项。
大图支持关闭按钮、Esc 和点击遮罩关闭。
本机官方图片导出接口没有 PSD 格式，本版不提供 PSD 导出。
连接展示节点只读取已有结果，不触发生图。
生成出图后自动连接一张展示卡；已经连接的展示卡继续更新，不重复创建。
生成卡的「查看结果」可以直接打开已生成图片，即使展示卡位于屏幕外也能查看。
连线使用水平切线的三次贝塞尔曲线，包含拖线时的预览线，不采用直角路径。
连线使用独立的 12px 点击命中区；输入口接线允许在圆点周围一倍宽高内松手。
空白处拖动框选卡片与连线，Delete 批量删除，沿用既有撤销和重做逻辑。

## 执行边界

只有点击生成节点的「生成」才向官方服务提交任务。
模型列表、尺寸计算、图片导入、生成、查询和结果落盘均调用 Maker 官方 SDK/服务。
插件不自行实现积分扣费，不通过模拟点击官方按钮或改写请求执行生成。
图片状态从官方记录恢复；未知结果保留原请求，不自动重试该请求，不阻塞其他独立任务。
点击取消立即结束本地等待并取消后续任务，显示“已取消”，已完成图片保留。
同时请求官方取消标记；尚未返回任务编号时，在原请求返回编号后补发取消。
官方服务可能继续完成已提交的远端计算，不保证取消能撤回计算或退还积分。
展示与分页只包含实际成功的图片，不将已取消、排队或失败任务计算成图片。
参考图片支持拖入 PNG/JPG/WebP 文件；网页图片链接受来源跨域限制，失败时显示原因。
透明化使用 Maker 官方 createBackgroundRemoval 程序识别纯色背景并处理边缘杂色，
保存为独立 PNG，原图保留，不调用 AI 生图；复杂背景可能无法自动识别。
接入透明化节点时，生成完成自动执行透明化，再输出到展示；不再自动旁路展示原图。
已有的生成到展示直连会转接到透明化输出。连接已有图片时立即处理，无需重新生图。
每张输入按来源路径缓存透明化成功结果，后续出图不会重复处理已完成图片。
透明化失败会显示错误并停止当前链路，不用原图代替处理结果。
透明 PNG 必须同时包含透明像素及可见前景才标记成功；旧缓存自动重新处理。
重复的同源展示连接合并为一个，无其他来源的冗余展示卡移除。

## 架构

- `graph.js`：唯一节点定义及状态模型，包含位置、尺寸、配置、连线和任务结果。
- `canvas.js`：独立 Shadow DOM 节点层；节点按 ID 保留，拖动只更新坐标。
- `maker.js`：唯一官方 SDK 适配层，提供资源、生成和只读样式、连线布局能力。
- `ownership.js`：持久记录插件任务归属，防止官方恢复流程把插件结果另建为平台卡片。

插件只读取官方画布的视口变换，不参与官方卡片的渲染生命周期。
卡片没有“便签”“生成草图”或“工作流”之类来自宿主的替换标题。
模型按项目和画布保存在扩展存储中，不随 Maker 模板 ZIP、Git 或云项目自动同步。
展示使用官方画布缓存的 `resultAssetPath`；发布目录的文件路径不能直接当作画布图片 URL。
加载画布时会按原请求编号恢复已有结果和缓存路径，不重新生图。
插件归属的生成记录只从官方卡片恢复视图中过滤；官方生成记录、源文件仍保留。
旧插件的已知节点会复制到独立数据模型；原始记录保留，仅隐藏对应旧显示。
Maker 未保存或仍有任务执行时，安装器不强制刷新页面。
正在生成时，开发重载工具会延后重载扩展，避免使当前生成上下文失效。

按用户要求，本版未运行测试、浏览器功能验收或付费生图。
